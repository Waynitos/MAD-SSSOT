# AA Output — The Case FOR Strict GA-First Execution

**Position: The Clean Sweeper rule must open and relink the GA assembly tree before any drawing is touched.**

---

Autodesk Inventor's reference model is fundamentally hierarchical, not flat. When Inventor opens a `.iam` file, it resolves child references by reading internal path records embedded in that `.iam`'s XML — these are absolute or vault-relative paths written at save time, pointing to each sub-assembly and part by their exact filename and location. The GA is the root of this resolution tree. Every `.iam` below it is resolved relative to the GA's own stored records, and every `.ipt` is resolved relative to its immediate parent assembly. Inventor does not consult drawings to discover models. The drawing is a downstream consumer that holds its own separate reference to a model view — but that model view must already be coherent before the drawing can correctly bind to it. This means the assembly tree's internal reference integrity is entirely independent of, and must precede, any drawing-level relinking. The hierarchy is not a convenience — it is Inventor's enforced data contract.

The current broken implementation inverts this contract by scanning drawings first to discover which models exist, then copying files, then attempting to update drawing references. This approach treats the drawing as an authority on assembly membership, which it is not. A drawing references a *view* of a model — it cannot enumerate the full sub-assembly tree, it cannot know about parts that have no drawing, and it cannot re-establish the parent-child path records stored inside each `.iam`. When files are copied to new filenames and new locations, every `.iam` in the copied tree still carries its old internal path records. At that moment, the copied GA is structurally broken: open it in Inventor and it immediately reports unresolved references, because the paths embedded in its XML still point to the old filenames. No amount of drawing-ref updating can repair this, because drawings do not write into `.iam` reference tables. The GA's internal wiring is broken and stays broken.

Copying files without relinking the GA first produces a tree that is physically present on disk but referentially dead. The copied sub-assemblies reference their old children by old names. The copied parts exist at new paths but are not registered in any parent. The result is a collection of orphaned files wearing new names, with no coherent assembly structure binding them. If the rule then attempts to update drawings to point at these new files, those drawings will open their new model references and find broken assemblies — missing components, suppressed features, incorrect mass properties — because the GA tree itself was never properly rewired. Any validation or BOM extraction run afterward will operate on a corrupted tree, producing results that look correct at the filename level but are structurally false.

GA-first execution follows Inventor's own resolution order exactly. The concrete sequence is: (1) build the full rename map — old path → new path — for every file in the GA tree, traversing depth-first from GA down through all sub-assemblies to leaf parts; (2) copy all files to their new locations; (3) open the copied GA in Inventor and walk the component tree, calling `ComponentDefinition.Occurrences` at each level to update each occurrence's `ReferencedFileDescriptor` to its new mapped path; (4) save every modified `.iam` before closing; (5) only then proceed to drawings. Steps 1–4 establish a fully coherent assembly tree. The GA, when re-opened after step 4, resolves all children cleanly. This is the state drawings require before they can bind correctly.

The validation rule that follows from GA-first is unambiguous: every model path that a drawing references must exist in the rename map built in step 1. If a drawing references a model path that is not in the GA map, that model is not a member of the copied GA tree — it is an orphan, and the rule must surface a hard `ORPHAN ERROR` for that drawing reference rather than silently copying or skipping it. This matters because orphaned drawing references are the most common symptom of the inverted (drawing-first) approach: drawings that reference models from a different project, an older revision, or a path outside the copied tree slip through undetected and corrupt the new project's BOM. GA-first execution makes the rename map the single source of truth; the drawing scan becomes a verification pass against that map, not a discovery mechanism. Anything not in the map is by definition an error, and the rule should halt and report it rather than proceed with a structurally incomplete copy.
