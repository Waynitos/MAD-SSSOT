# DA Output — Against Naive GA-First Execution in Clean Sweeper TRAVERSE Rule

**Position argued: The "open GA first, relink it, then handle drawings" strategy is structurally fragile and should be replaced by a copy-atomic-first, level-by-level relink, drawing-validate-last sequence.**

---

### 1. "Open the GA and Relink" Is Not a Single Operation — It Is a Precondition Stack

The appeal of opening the GA first rests on a false premise: that opening one `.iam` file gives you a fully addressable document graph. It does not. Inventor's document model is lazy by default. When a GA is opened, Inventor resolves its direct children, but sub-assemblies at depth 2 and beyond are opened in a *lightweight* or *suppressed* state unless explicitly forced to full resolution. `ReferencedDocumentDescriptors` on a sub-assembly that has not been fully loaded will return stale or incomplete descriptor sets — the API does not throw; it simply operates on what is in memory. This means a call to `ReplaceReference` on a sub-assembly that Inventor has not promoted to full open state will silently succeed on the descriptors it can see, leave the rest untouched, and return no error. You will not know which references were missed until a downstream open fails. With 9,414 occurrences in the PRE_Tree, the probability of at least one sub-assembly being in a lightweight state at relink time is not theoretical — it is near-certain in any real project tree.

---

### 2. Depth Is the Killer — GA-Level Relinking Only Fixes Direct Children

Even if you force the entire tree to full load (which carries its own cost and failure modes — Vault proxies, missing files, licence seats), `ReplaceReference` operates on the *calling document's* descriptor list, not the tree. Relinking at the GA level fixes the GA's own references to its direct children. It does not cascade. Each sub-assembly at depth N holds its own `ReferencedDocumentDescriptors` pointing to depth N+1 parts and assemblies, and those descriptors still carry the old file paths. The GA relink pass leaves every intermediate assembly in a split state: its own path is new, but the paths it holds internally are old. This is not a theoretical concern about edge cases — it is the documented behaviour of the Inventor COM document model. A "GA-first" strategy applied without explicit per-node descent is equivalent to renaming the root of a directory tree and leaving every subdirectory's internal symlinks pointing to the old location. The rule's existing PRE_Tree walk already captures the full depth-ordered occurrence list precisely because per-node relinking is unavoidable. Pretending the GA is a shortcut past that list is ignoring what the PRE_Tree was built to solve.

---

### 3. Drawing-Scan-First Surfaces References That the GA Walk Can Miss

The PRE_Tree is derived from a GA assembly walk. That walk captures model-to-model references — components inside assemblies. But drawings (`.idw` / `.dwg`) reference models independently, and those references are not encoded in the assembly tree. A drawing may reference a sub-assembly at depth 4 directly — perhaps a detail view, a section, or a BOM balloon that was drawn from a mid-tree assembly rather than the GA. These drawing-to-model references are entirely invisible to a GA walk. If the execution strategy opens the GA first and starts relinking before a drawing scan has been completed, you can find yourself in a state where: (a) the new model files exist under new names, (b) the GA and its assembly tree have been partially or fully relinked to those new names, but (c) a drawing that holds a direct reference to the old path of `SUB-003-V01-02-000.iam` is now pointing to a file that no longer exists at that path and has not yet been told its new location. A drawing-scan-first pass, by contrast, builds a *complete* reference map — assembly refs plus drawing refs — before a single file is renamed or relinked. That map is the only guarantee that no reference falls through the gap between the assembly walk and the drawing walk.

---

### 4. Relinking Before Atomic Copy Is Operational Roulette

The most dangerous failure mode in a GA-first strategy is the mid-operation partial state. Consider: the rule begins opening the GA, starts relinking references to new filenames, processes 400 of 600 sub-assemblies — and then a file copy fails (network drop, Vault lock, insufficient permissions, path length violation on a deeply nested node). At this point the state of the document set is: some old files have been copied and relinked to new names, the GA and some subs hold new paths in their descriptors, but the remaining subs still hold old paths — and the old files at those paths may or may not still exist depending on whether the copy step was destructive. Recovering from this requires a rollback that the current rule has no mechanism to perform, because the relink step is not idempotent and Inventor does not provide a transactional undo for `ReplaceReference` across a document graph. The only safe execution contract is: **all file copies must complete and be verified before any relinking begins.** Copy is an atomic precondition. Relinking is a post-condition. Interleaving them — which a GA-first open-and-relink strategy implicitly does — removes the ability to abort cleanly at any point.

---

### 5. The Correctly Sequenced Hybrid: Copy-Atomic, Then Level-by-Level Relink, Then Drawing Validation

The robust sequence is not "GA first" or "drawings first" — it is phase-separated. **Phase 1 (Scan):** Walk the GA tree to build PRE_Tree; independently scan all drawings to collect their direct model references; merge into a single OLD→NEW path map, flagging any drawing references that point outside the GA tree. **Phase 2 (Copy — atomic):** Copy every file in the map to its new location. Do not open any document for editing. Verify every copy succeeded before proceeding. If any copy fails, stop and report — no relink has occurred, no original is damaged. **Phase 3 (Relink — depth-ordered):** Open each document in depth-last order (leaves first, GA last). For each, iterate `ReferencedDocumentDescriptors`, look up each old path in the map, call `ReplaceReference` with the new path, save and close. Depth-last ordering ensures that by the time a parent assembly is opened for relinking, its children's new files already exist and are closed-and-saved with their own corrected descriptor sets — Inventor can resolve them cleanly. **Phase 4 (Drawing validation):** Open each drawing, verify its model references resolve against the map, correct any that do not, save. This phase is last because drawings are consumers of the model tree, not participants in it — their correctness depends on the model relink having completed successfully. This sequence is slower than a naive GA-first pass, but it is the only sequence that is safe to interrupt, safe to retry, and safe to audit.
