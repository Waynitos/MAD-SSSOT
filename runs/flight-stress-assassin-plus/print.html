Section 3
Three-Phase Build Plan
Build in this order. Phase 1 alone eliminates most search stress.
01
The Launcher
Build time: 1 day · Cost: $0
Input form takes origin, destination, date range, stops, baggage, time windows, airlines. Generates pre-filtered deep-links for Google Flights, Skyscanner, Qantas, Virgin, Jetstar. One click opens all in parallel tabs. Zero scraping. Zero ToS risk. Zero maintenance. Eliminates re-entering the same data into five sites every time.
02
The Intelligence Layer
Build time: 1 week · Cost: $0/month (free tier)
Amadeus Self-Service API adds: cheapest day in a date range, price trend signal (is today high or low vs 90 days?), seat availability alerts, threshold price notifications. Dashboard shows all active searches and alerts in one view. Covers full-service carriers (Qantas, Emirates, Singapore, Virgin). LCCs handled by Phase 1 launcher.
03
The LCC Bridge
Build when needed · Optional
Claude-in-Chrome attaches to user's existing authenticated Jetstar/AirAsia session. Manual trigger only — not scheduled. Extracts prices, merges into dashboard alongside Amadeus data. Used sparingly for LCC routes not covered by Amadeus. Treat as a research signal, not a booking source — always verify on site.

Section 4
7 Critical Failure Modes to Avoid
Identified by the DA. None are caught by standard development planning.
1
Don't scrape without user session. Cloudflare/Akamai fingerprints canvas rendering, WebGL, TLS hash, mouse entropy. A headless Playwright session is detectable within seconds. Will be blocked within days. Use Amadeus API or the user's own authenticated Chrome session instead.
2
Don't trust scraped prices as bookable. Prices change every 30–90 seconds. Any price shown is a snapshot at time of query. Always verify on the airline site before any purchase. Build a "verify on airline site" button into the UI — make it the default next step.
3
Don't try to cover all airlines on day one. Start with Amadeus (400+ full-service carriers) + Google Flights deep-link (covers LCCs via the site). Add Claude-in-Chrome LCC bridge incrementally when a specific gap is felt. Trying to cover everything at launch means shipping nothing.
4
Don't build a background scheduling service for scraping. Scheduled automated sessions on airline sites = ToS violation. Loyalty account termination risk (points gone). Use on-demand search only. Price alerts via Amadeus API are fine — that's using an authorised data channel.
5
Don't attempt to automate the booking step. Seat selection, payment, confirmation are always manual and always on the airline site. The tool's job is search aggregation and handoff — not end-to-end booking. Attempting booking automation introduces payment failure modes and zero benefit.
6
Don't conflate "price found" with "deal confirmed." The UI must always show data freshness (timestamp of last query) and include a prominent "verify before buying" warning on every result. A user who acts on a stale price will blame the tool, not the airline's dynamic pricing system.
7
Don't let "AI said so" replace the tool. The origin story of this project is an AI that gave bad flight advice because it had no real data. This tool must never give a price recommendation without showing its data source, its freshness, and its limitations. Data transparency is non-negotiable.
