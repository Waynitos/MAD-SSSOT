# AA — Strongest Case FOR GA-Tree-First Approach

The drawing-refs-only scan was architecturally incomplete from the start: drawings reference individual sub-assemblies they happen to depict, while the GA is the authoritative source of truth for the complete component tree. These two sets will never be identical — drawings are selective views, the GA is the whole. Any integrity pass built solely on drawing refs is therefore guaranteed to miss GA children that no drawing directly references, exactly as this run proves. The GA-Tree-First fix closes this gap at the only correct point: Step 2, before the user commits any renames. Walking `ComponentDefinition.Occurrences` at depth 1 is a standard, crash-stable Inventor API call used in thousands of iLogic rules — it carries none of the fragility of Replace() or FileDescriptor manipulation. Surfacing GA children in the same rename form the user already works through is not extra friction; it is the disclosure the user needed all along — they can see every file that will be rewired in one place and confirm or correct each mapping explicitly. This eliminates all fuzzy matching, all assumptions about naming conventions, and all silent failures. The GA-discovery fix (scan all drawings, file-picker fallback) simultaneously removes the brittle dependency on the active drawing having refs — the rule becomes runnable from any drawing in the set, including a title-block-only sheet with zero model refs, which is precisely the failure mode observed in this run.
