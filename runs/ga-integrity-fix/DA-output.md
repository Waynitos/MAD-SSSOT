# DA — Against GA-Tree-First; For Target-Folder Match at Integrity Time

GA-Tree-First frontloads a significant risk: opening a large, potentially complex assembly *before* the user has confirmed the rename form means Inventor must resolve and load every reference in that tree — including broken ones, suppressed ones, and any Design Accelerator virtuals — right at the worst possible moment. If that open triggers a resolve dialog, a Vault checkout prompt, or a crash (as already observed in this project), the user loses the run before they've even filled in a single name. Worse, the form then balloons: instead of a focused list of drawing-referenced models the user actually knows about, it includes every GA sub they may have never named, creating decision fatigue and a higher probability of wrong mappings. The Target-Folder Match approach sidesteps all of this — the GA is never touched until the copy phase is already successful and the target folder is populated with ground-truth files stamped with this run's timestamp. At that point, matching an unresolved GA child against `File.GetLastWriteTime`-filtered target inventory is deterministic: if exactly one copied file matches (same prefix, same file was created in this run window), it's an unambiguous replacement. The GA discovery fix — scan all drawings' refs for `.iam` rather than only the active drawing — is a two-line change independent of either approach and must be done regardless.
