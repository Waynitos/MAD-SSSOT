### FINDINGS

**1. [CRASH RISK] Pre-Phase 2 document lifecycle — opened files never closed**  
_PRE-PHASE 2 block_  
Every `.IAM`, `.IPT`, `.IDW`, `.DWG` already in the target folder is opened via `ThisApplication.Documents.Open(sPRFile, False)` to read `CS_SourcePath`. The comment says `' Don't close — may already have been open; Phase 2 will handle lifecycle'`. But Phase 2's close guard only fires when `bOpenedHere2 = True` — which only tracks documents Phase 2 itself opened. Files opened solely in PRE-PHASE 2 (prior-run files not in `oMapKeys`) are never closed. On large projects with 100+ prior files in the target folder, this silently accumulates open Inventor documents throughout the run, risking session memory pressure and instability.  
**Suggested fix:** Track a separate `oProvRebuildOpened` list of `Document` objects opened in PRE-PHASE 2, and close them in the `Finally` block alongside the SilentOperation restore.

---

**2. [CRASH RISK] Silent SaveAs success when output file not created**  
_Phase 2 SaveAs block: `bSaveAsOk2 = System.IO.File.Exists(sNewFull2)`_  
If `oDoc2.SaveAs(sNewFull2, True)` completes without throwing but the file is not on disk (a silent no-op — can occur with Vault-managed read-only documents), `bSaveAsOk2` is `False` and `iSaveFailed` increments but no log entry identifies this specific case. The user sees a failed count but no log line to diagnose it.  
**Suggested fix:** Add a log line in the `Else` branch: `"SAVEAS-SILENT-FAIL: " & sOldName2 & " — SaveAs returned no exception but file not found on disk"`.

---

**3. [CRASH RISK] Null-dereference on TryCast in Phase 3 Occurrence block**  
_Phase 3, 3b block: `Dim oAsmDef3 As AssemblyComponentDefinition = TryCast(oDoc3, AssemblyDocument).ComponentDefinition`_  
`TryCast` returns `Nothing` if `oDoc3` is not an `AssemblyDocument`. Chaining `.ComponentDefinition` immediately on a potential `Nothing` throws a `NullReferenceException`. The outer `Catch exOcc3` catches it, but Phase 3 ref-fixing silently aborts for that file. Since the loop already filters `If sExtU3 = ".IAM"`, this is unlikely in practice — but a corrupt `.IAM` that opens as a generic `Document` would hit it.  
**Suggested fix:** Split into two lines:
```vb
Dim oAsmDoc3 As AssemblyDocument = TryCast(oDoc3, AssemblyDocument)
If oAsmDoc3 Is Nothing Then Continue For
Dim oAsmDef3 As AssemblyComponentDefinition = oAsmDoc3.ComponentDefinition
```

**4. [ILOGIC] PRE-PHASE 2 opens .DWG/.IDW files from the target folder**  
_PRE-PHASE 2 file filter includes `.IDW` and `.DWG`_  
Drawings in the target folder still reference OLD model paths — Phase 3 hasn't run yet. Opening them triggers Inventor's internal reference resolution. `SilentOperation = True` suppresses most dialogs but not all Vault-managed reference prompts on drawings. `CS_SourcePath` is never written to drawings (only to models), so they always return `sCSSource = ""` and contribute nothing to `oActualMap`. The opens are pure overhead with dialog risk.  
**Suggested fix:** Restrict the PRE-PHASE 2 file scan to `.IAM` and `.IPT` only.

---

**5. [ILOGIC] WalkTree opens child documents during Phase 1 but never closes them**  
_WalkTree: `oChild = ThisApplication.Documents.Open(sRefPath, False)`_  
Phase 1 opens every child `.IAM`/`.IPT` encountered but tracks no `bOpenedHere` flag. For large assemblies (500+ parts), all parts end up concurrently open in the Inventor session before Phase 2 begins, consuming significant memory.  
**Suggested fix:** Collect newly-opened documents in `WalkTree` into a passed-in `oWalkOpened As List(Of Document)` list; close them in `Sub Main` after the rename map is confirmed but before Phase 2 starts.

---

**6. [ERROR HANDLING] Silent provenance omission when new-file open fails after SaveAs**  
_Phase 2: `If oNewDoc2 IsNot Nothing Then ... End If` — no log on the Nothing path_  
When `SaveAs` succeeds but `Documents.Open(sNewFull2, False)` fails, provenance properties are never written — yet the file is counted as `iSaved += 1`. The user has no way to identify files saved without provenance from the summary.  
**Suggested fix:** Add a `"SAVED-NO-PROV: " & sNewName2` log entry and optional `iNoProvenance` counter in the final summary.

---

**7. [OPTIMISATION] O(n²) collision guard — `Dictionary.ContainsValue()` is O(n)**  
_WalkTree + top-assembly block: `Do While oRenameMap.ContainsValue(sTestFull) OrElse System.IO.File.Exists(sTestFull)`_  
`Dictionary.ContainsValue()` is a linear scan: O(n). With 1,000 files and multiple collisions the collision guard becomes O(n²).  
**Suggested fix:** Maintain a parallel `oMappedTargets As New HashSet(Of String)(StringComparer.OrdinalIgnoreCase)`. Replace `oRenameMap.ContainsValue(sTestFull)` with `oMappedTargets.Contains(sTestFull)` for O(1) lookup.

---

**8. [OPTIMISATION] Redundant `GetFiles` scan at Phase 3 start**  
_Phase 3 P3Targets build: `Directory.GetFiles(sTargetFolder, "*.iam", ...)`_  
`oTargetByBase` was already populated by a full `GetFiles("*.*")` scan earlier in Phase 3. Scanning again for `"*.iam"` is a redundant disk I/O call.  
**Suggested fix:** Filter `oTargetByBase.Values` by `.IAM` extension instead of calling `GetFiles` again.

---

**9. [OPTIMISATION] PRE-PHASE 2 opens all prior-run target files — expensive for mature projects**  
_PRE-PHASE 2: `Directory.GetFiles(sTargetFolder, "*.*", ...)`_  
On a mature project with 200+ prior-run files in the target folder, PRE-PHASE 2 opens all of them. Only files whose `CS_SourcePath` matches a source in `oRenameMap` are useful — the rest are opened for nothing.  
**Suggested fix:** Pre-compute expected new filenames from `oRenameMap.Values` and limit the PRE-PHASE 2 scan to only target files whose basename matches an expected new filename.

### VERDICT: **Moderate**

The script is well-structured with good phase isolation, explicit SilentOperation management, and solid fallback paths (File.Copy fallback, Save2→Save fallback). No single issue will crash a typical run. The key concerns for production use:

- **Finding 1** (PRE-PHASE 2 lifecycle) is the most impactful — on a project where the target folder grows over successive runs, unbounded document accumulation is a real session stability risk.
- **Findings 7 & 9** (O(n²) guard + broad PRE-PHASE 2 scan) will cause noticeable slowdowns on large assemblies.
- **Findings 3 & 5** (TryCast null-chain, WalkTree unclosed docs) are lower-risk but straightforward to fix.
