## SCRIPT 1: scripts/ilogic/SUPER_CLEAN_SWEEPER.iLogicVb
**Commits:** `8575a6e` (initial add) → `453d228` (compile fix — helpers after Sub Main, CC check via IsContentMember)

### FINDINGS:

**1. [ILOGIC — MODERATE] WalkTree: CC-part document leaked open after `IsContentMember` early-exit**

```vb
If oChild Is Nothing Then
    Try
        oChild = ThisApplication.Documents.Open(sRefPath, False)
    Catch ... Continue For
    End Try
End If
' F3: Sub-type check on the open document
Try
    If oChild.DocumentType = DocumentTypeEnum.kPartDocumentObject AndAlso _
       oChild.ComponentDefinition.IsContentMember Then
        ' ... log entry ...
        Continue For   ' ← BUG: oChild was opened fresh above, never closed
    End If
Catch : End Try
WalkTree(oChild, ...)
```

When a child document is NOT already in the Inventor session, `Documents.Open` opens it fresh. If that freshly-opened document is then identified as a Content Centre part via `IsContentMember`, the code executes `Continue For` without closing the document first. In a large assembly with many CC fasteners/bolts, this leaks dozens of open documents into Inventor's session, degrading memory and performance for the duration of the job.

**Suggested fix:** Introduce a `bChildOpenedHere As Boolean` flag; set it `True` after the `Documents.Open` call; before every `Continue For` on the CC-skip path, call `Try : oChild.Close(True) : Catch : End Try` when `bChildOpenedHere`.

**2. [CRASH RISK — MINOR] Final log-write `WriteAllText` calls not wrapped in Try/Catch**

```vb
' SNAPSHOT mode, line ~290:
System.IO.File.WriteAllText(sSnapPath, oSB.ToString())

' PROBE mode, line ~487:
System.IO.File.WriteAllText(sLogPath, oLog.ToString())
```

Both calls write the entire result to Desktop after completing all diagnostic work. Neither is wrapped in a Try/Catch. If the Desktop path is unavailable (network Desktop, permissions change, disk full), the script crashes at the final step and the user sees an unhandled exception — losing a potentially complete log.

**Suggested fix:** Wrap both calls in Try/Catch; on failure, show a `MessageBox` displaying the first ~2000 characters of the log inline so the user gets the diagnostic output even if disk write fails.

## SCRIPT 4: scripts/ilogic/INVENTOR_EVENT_CAPTURE.iLogicVb
**Commit:** `06eb94c` — Code-Assassin fixes applied (handler leak, defensive RemoveHandler, g_sLogPath cache, UserInputEvents switch all present)

### FINDINGS:

**1. [ILOGIC — MINOR] Line 51: `g_sLogPath` declared as bare `Dim`, not `Private Shared`**

```vb
Dim g_sLogPath As String = ""
```

The script's own compiler notes at line 33 explicitly warn: "Do NOT place bare Dim at outer scope." This declaration is at the outer scope. While this may work if the iLogic host keeps the compiled instance alive between the START run and the STOP run (which the event subscription encourages), it is not guaranteed. `Private Shared` would guarantee state persistence across invocations regardless of host behaviour.

**Suggested fix:** Change to `Private Shared g_sLogPath As String = ""`

---

**2. [CRASH RISK — MINOR] Line 174: `File.Delete(sSentinel)` unprotected inside `Catch exHook`**

```vb
Catch exHook As Exception
    g_sLogPath = ""
    System.IO.File.Delete(sSentinel)   ' ← no Try/Catch
    MessageBox.Show(...)
    Return
End Try
```

This is the AddHandler failure path. If `File.Delete(sSentinel)` throws (sentinel file locked by another process, or file was already deleted externally), the exception propagates uncaught from `Sub Main`, preventing the error `MessageBox` from ever showing — the user sees no feedback about the hook failure.

**Suggested fix:** Wrap the `Delete` call in `Try : System.IO.File.Delete(sSentinel) : Catch : End Try`

**VERDICT: Minor**
