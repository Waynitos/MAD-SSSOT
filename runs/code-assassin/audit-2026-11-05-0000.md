### FINDING 1 — [ILOGIC] Line ~163–173: Drawing entry doc opened but not tracked for closure

**New in v2.2.8.**  
When the rule is started from a drawing (`bFromDwg = True`), if the referenced `.iam` model is not already open in Inventor's session, it is opened at line 170:
```vb
oEntryDoc = ThisApplication.Documents.Open(sEntryModel, False)
```
There is no `bEntryDocOpenedHere` flag. If the user then cancels the folder browser dialog (line 212–215) or the new-prefix input box (line 232–235), the script exits via `Exit Sub` without closing `oEntryDoc`. The document remains in Inventor's session and may accumulate as unsaved state across repeated runs.

**Suggested fix:**  
Add `Dim bEntryDocOpenedHere As Boolean = False` before the open call at line 169, set it to `True` after a successful open, and in each early `Exit Sub` path (folder cancel, prefix cancel), add:
```vb
If bEntryDocOpenedHere AndAlso oEntryDoc IsNot Nothing Then
    Try : oEntryDoc.Close(True) : Catch : End Try
End If
```

### FINDING 2 — [ILOGIC] Line ~151–160: `oActiveDoc.ReferencedFileDescriptors` not wrapped in Try

**New in v2.2.8 (drawing entry path).**  
The `For Each oEntryFD In oActiveDoc.ReferencedFileDescriptors` loop on line 151 is NOT wrapped in a Try block. Only `oEntryFD.FullFileName` on line 154 is guarded. If the drawing is in an error state (unresolved references, partially loaded, Vault-locked) and the FileDescriptors collection itself throws a COM exception, the exception propagates as an unhandled error from Sub Main, crashing the rule with no log entry and no user message.

**Suggested fix:**  
Wrap lines 151–160 in a Try/Catch:
```vb
Try
    For Each oEntryFD In oActiveDoc.ReferencedFileDescriptors
        ...
    Next
Catch : End Try
```

### FINDING 3 — [ILOGIC] Line ~721: Phase 2 provenance save uses `Save()` instead of `Save2(False)`

**Existing since at least v2.2.3; not changed in recent commits but deserves noting.**  
When writing provenance properties to a new file and saving (line 721), the code calls `oNewDoc2.Save()` — the full Inventor Save. For `.iam` assembly files, this cascades to ALL dirty dependents in the session, which can pop Vault multi-file-save dialogs even when `SilentOperation = True` (Vault overrides SilentOperation for multi-file prompts). Every other save in this script correctly uses `Save2(False)` to prevent cascade. This is an inconsistency that becomes more likely to cause dialog hangs as Phase 2 processes larger assembly trees.

**Suggested fix:**  
Change line 721 from:
```vb
oNewDoc2.Save()
```
to:
```vb
oNewDoc2.Save2(False)
```

### FINDING 4 — [ILOGIC] Line ~1096–1115: Drawing relink FD loop iterates live collection without snapshot

**New in v2.2.8.**  
The Drawing Relink phase iterates `oDwgR.ReferencedFileDescriptors` directly in a `For Each` loop while calling `oDwgFD.ReplaceReference(sDwgNew)` inside. Modifying a COM object's collection during live enumeration can cause COM exceptions (`COMException: Collection was modified`) or silently skip entries in some Inventor versions. Phase 3 and Phase 4 both snapshot occurrences/descriptors into a `List(Of ...)` before iterating — the Drawing Relink should do the same. Risk is low for a typical drawing with 1–3 model refs but could become a problem for multi-sheet drawings with many referenced models.

**Suggested fix:**
```vb
Dim oDwgFDs As New System.Collections.Generic.List(Of FileDescriptor)()
Try
    For Each oDwgFD In oDwgR.ReferencedFileDescriptors : oDwgFDs.Add(oDwgFD) : Next
Catch : End Try
For Each oDwgFD In oDwgFDs
    ' ... existing replace logic ...
Next
```

### FINDING 5 — [ILOGIC] Line ~1086–1127: Drawing opened in relink phase not tracked in `oProvRebuildOpened`

**New in v2.2.8.**  
When `bDwgOpenedHere = True` and `Save2(False)` fails (`bDwgSaved` stays False), the drawing is left open (intentional per v2.2.4 design). However, `oDwgR` is NOT added to `oProvRebuildOpened`, so the F1 `Finally` block at lines 1136–1143 does NOT close it. If an unexpected exception also fires inside the Drawing Relink block and propagates past the inner `Catch exDwg`, the F1 Finally still cannot clean up `oDwgR`. On repeated failed runs, Inventor's session accumulates open drawing documents.

**Suggested fix:**  
After opening `oDwgR` and before returning from that path, add it to the cleanup list:
```vb
If bDwgOpenedHere AndAlso oDwgR IsNot Nothing Then oProvRebuildOpened.Add(oDwgR)
```
so the F1 Finally always has the chance to close it.  
Alternatively, add a dedicated `Finally` inside the Drawing Relink block.

### FINDING 6 — [OPTIMISATION] Line ~780–791: `oTargetByBase` built from `GetFiles("*.*")` includes non-model files

**Existing since v2.2.4.**  
`oTargetByBase` is built by scanning `*.*` in the target folder. For large target folders (100+ files), this indexes PDFs, DWGs, log files, etc. — none of which are referenced by `.iam` occurrences or FileDescriptors. The index is used only as a basename fallback for `.iam`/`.ipt` refs in Phase 3 and Phase 4.

**Suggested fix:**  
Use two calls to narrow the scan:
```vb
For Each sTF As String In System.IO.Directory.GetFiles(sTargetFolder, "*.iam", SearchOption.TopDirectoryOnly)
    ...
Next
For Each sTF As String In System.IO.Directory.GetFiles(sTargetFolder, "*.ipt", SearchOption.TopDirectoryOnly)
    ...
Next
```
On a 500-file target folder this reduces the index to only the files that matter (~10×), speeding up Phase 3 and 4 baseline setup.
