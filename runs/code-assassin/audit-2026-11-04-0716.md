**1. [CRASH RISK / ILOGIC] Line ~3680-3685: GA-RESOLVE silently drops orphan when GA WIP key already exists in oRenameMap**

```vb
oRenameMap.Remove(sOldKey)
If Not oRenameMap.ContainsKey(sGaMatchFull) Then
    oRenameMap.Add(sGaMatchFull, sOldValue)
End If
```

If `sGaMatchFull` (the GA WIP file's full path) is already a KEY in `oRenameMap` — which happens when the preset or form map already included that GA WIP file — the guard blocks the `Add` but `Remove(sOldKey)` has already fired. The orphan's target entry (`sOldValue`) is permanently lost. The drawing will reference a file that was never copied.

**Suggested fix:** Check the guard BEFORE removing: `If oRenameMap.ContainsKey(sGaMatchFull) Then oStillOrphans.Add(sOrphanBase) : Continue For` — treat as still-orphan rather than silently dropping.

**2. [ILOGIC] Line ~3663-3668: Stem-match iterates a HashSet — first-found, non-deterministic order**

```vb
For Each sGaCand As String In oGaAllBasenames
    If sGaCand.IndexOf(sStem, StringComparison.OrdinalIgnoreCase) >= 0 Then
        sGaMatchBase = sGaCand : Exit For
    End If
Next
```

`oGaAllBasenames` is a `HashSet(Of String)` — enumeration order is not guaranteed. If the GA has two members whose basenames both contain the stem (e.g. `TANK ASSEMBLY` and `TANK ASSEMBLY VARIANT`), whichever the runtime happens to enumerate first wins. This can produce a wrong copy source across runs with no visible indication.

**Suggested fix:** Select the shortest matching basename (closest match to the stem) instead of first-found, giving predictable and usually correct results.

## SCRIPT 3: scripts/spellcheck/BomExtractorSweeper.py
**Commit:** `e343ae3` — Add files via upload (new file, 3548 lines)

### FINDINGS:

**1. [CRASH RISK] Line ~293-310: Second `_Tee` class shadows first — `open()` without try/except**

The file defines two classes both named `_Tee`. The first (line 54) wraps `open()` in try/except and silently falls back if the log file can't be created. The second (line 293) shadows it and calls `open()` bare:

```python
class _Tee:                                # second definition — overwrites first
    def __init__(self, log_path):
        self._file = open(log_path, "w", encoding="utf-8", errors="replace")  # no try/except
```

Any code after line 293 that instantiates `_Tee(log_path)` where `log_path` is on a network drive (`G:\Drawing Office\...`) will raise `FileNotFoundError` / `OSError` if that drive is unavailable, crashing the script before any user-facing error.

**Suggested fix:** Mirror the first class: wrap `open()` in try/except, set `self._file = None` on failure, and guard all file writes with `if self._file`.

---

**2. [OPTIMISATION] Line ~1113-1127: AutoCAD gap filter samples only the first 4 inter-row gaps**

```python
sample = sorted(gaps_up[:min(4, len(gaps_up))])
min_bom = sample[0] if sample else 8.0
```

If the first few rows are abnormally spaced (merged cells, header bleed), `min_bom` will be wrong and the filter may cut the BOM short or over-extend into the notes section. Using the median of all inter-row gaps rather than the minimum of the first 4 would be more robust.

**VERDICT: Moderate**
(The second _Tee crash risk is real and triggered whenever the network log path is unavailable at the wrong moment. Rest of the extraction logic looks solid.)
