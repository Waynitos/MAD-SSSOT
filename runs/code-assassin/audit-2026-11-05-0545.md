**1. [ILOGIC] Line ~1191: Document session leak on TryCast failure (Phase 3)**
Inside the Phase 3 loop, when `sExtU3 = ".IAM"` and `TryCast(oDoc3, AssemblyDocument)` returns `Nothing` (corrupt or non-standard .iam), `Continue For` exits the iteration before the close guard at lines 1296–1301:
```vb
If bSaved3 AndAlso bOpened3 AndAlso oDoc3 IsNot Nothing Then
    Try : oDoc3.Close(True) : Catch : End Try
End If
```
If `bOpened3 = True` the document stays open in the Inventor session, accumulating until the script ends. Low probability (normal .iam files always cast to AssemblyDocument), but on a large tree with partially-corrupt files this could grow.
**Suggested fix:** Add a close guard directly before the `Continue For`:
```vb
If oAsmDoc3 Is Nothing Then
    If bOpened3 AndAlso oDoc3 IsNot Nothing Then Try : oDoc3.Close(True) : Catch : End Try
    Continue For
End If
```

**2. [ILOGIC] Line ~1434 / Finally ~1503: Drawing document double-close**
When the script starts from a drawing (`bFromDwg = True`) and the drawing is opened here, it is added to `oProvRebuildOpened` (FIX E) so the outer Finally can clean it up. However, within the Drawing Relink block it is also explicitly closed if `bDwgOpenedHere AndAlso bDwgSaved` (line 1479–1481). The Finally then attempts to close it a second time. The inner Try/Catch absorbs the error silently, but on a Vault-managed document the second close can trigger an unexpected "file modified in session" prompt even with `SilentOperation = True`, since `SilentOperation` is restored to `bOrigSilent` *before* the double-close attempt.
**Suggested fix:** After closing `oDwgR` at line 1480, remove it from `oProvRebuildOpened`:
```vb

    Try : oDwgR.Close(True) : Catch : End Try
    oProvRebuildOpened.Remove(oDwgR)   ' ← prevent double-close in Finally
End If
```

**5. [CRASH RISK] Line ~838: `CInt(sRunStr)` without parse guard**
```vb
Dim sRunStr As String = oDoc2.PropertySets(...).Item("CS_RunCount").Value
iRunCount2 = CInt(sRunStr) + 1
```
If `CS_RunCount` was written by an external tool as a floating-point string (e.g. `"1.0"`), or reaches `Integer.MaxValue` (2,147,483,647), `CInt` throws `OverflowException` or `InvalidCastException`. The outer `Catch` resets `iRunCount2` to 1, silently losing the chain counter. The fix is cheap:
**Suggested fix:**
```vb

If Integer.TryParse(sRunStr, iTmp) Then
    iRunCount2 = If(iTmp >= 9999, 9999, iTmp + 1)
End If
```
