## SCRIPT 1: scripts/ilogic/DIAGNOSTIC_RELINK_PROBE.iLogicVb

Commit: cd7f856 — Fix: fully qualify Environment.GetFolderPath/SpecialFolder (iLogic host ambiguity)

### FINDINGS:

1. **[CRASH RISK — CRITICAL]** Line 42: Bare `Environment.GetFolderPath(Environment.SpecialFolder.Desktop)` without `System.` prefix.  
   In the iLogic VB.NET host, `Environment` is shadowed by Inventor's own `Environment` namespace object. This causes a compile error: `'GetFolderPath' is not a member of 'Environment'` and `'SpecialFolder' is not a member of 'Environment'` — the script **will not compile** in Inventor.  
   This is exactly the same bug just fixed in `INVENTOR_EVENT_CAPTURE.iLogicVb` (commit cd7f856). The fix needs applying here too.  
   **Suggested fix:** Change line 42 to:  
   `Dim sDesktop As String = System.Environment.GetFolderPath(System.Environment.SpecialFolder.Desktop)`

2. **[ILOGIC — MODERATE]** Lines 28–31: Explicit `Imports System.IO`, `Imports System.Windows.Forms`, `Imports System.Collections.Generic`, `Imports System.Text.RegularExpressions`.  
   The INVENTOR_EVENT_CAPTURE header comment (the script this was developed alongside) explicitly warns: *"Do NOT add Imports System.IO or Imports System.Windows.Forms (pre-imported; duplicates cause Inventor.File / System.IO.File ambiguity)"*. These Imports are pre-loaded by the iLogic host. Duplicating them can cause the compiler to prefer `System.IO.File` over `Inventor.File` or vice versa, breaking FileDescriptor and Document operations silently.  
   **Suggested fix:** Remove all four `Imports` lines. Use fully-qualified names (`System.IO.Path.Combine`, `System.Text.RegularExpressions.Regex`) where needed — the rest are already pre-imported.

3. **[ILOGIC — MINOR]** Line 134: `Path.Combine(sDesktop, ...)` — once Imports System.IO is removed, this needs to be `System.IO.Path.Combine(sDesktop, ...)` for consistency and to avoid the same host-shadowing issue.  
   **Suggested fix:** Fully qualify as `System.IO.Path.Combine(...)`.

**VERDICT: Critical** — script will not compile in Inventor due to bare `Environment.GetFolderPath` on line 42.

## SCRIPT 2: scripts/generate-mad-pdf.py

Commit: 60429f4 — Add files via upload (initial)

### FINDINGS:

1. **[CRASH RISK — MODERATE]** Zero exception handling in the entire file (confirmed: 0 `try:`, 0 `except` blocks).  
   `asyncio.run(render_pdf(...))` on line 535 will crash with an unhandled exception if:
   - Playwright is not installed (`ModuleNotFoundError: No module named 'playwright'`)
   - Chromium is not found or fails to launch
   - The HTML page load times out (30s timeout fires)
   - The PDF write fails (permissions, disk full)  
   **Suggested fix:** Wrap `main()` body in a try/except and wrap `render_pdf` await calls individually:
   ```python
   async def render_pdf(html_path, pdf_path):
       try:
           from playwright.async_api import async_playwright
           async with async_playwright() as p:
               browser = await p.chromium.launch()
               ...
       except Exception as e:
           raise RuntimeError(f"PDF render failed: {e}") from e
   ```
   And in `main()`:
   ```python
   try:
       asyncio.run(render_pdf(html_tmp, pdf_out))
   except Exception as e:
       print(f"ERROR: {e}"); sys.exit(1)
   ```

2. **[CRASH RISK — MINOR]** Line 537: `size = pdf_out.stat().st_size` — if `render_pdf` fails silently and no PDF was written, this raises `FileNotFoundError` with no graceful message.  
   **Suggested fix:** Guard with `if pdf_out.exists(): size = pdf_out.stat().st_size` else print error and exit.

3. **[MISSING ERROR HANDLING — MINOR]** Line 531: `html_tmp.write_text(html, encoding='utf-8')` — no handling if `/tmp/` write fails (read-only mount, disk full). Low probability but worth a try/except with `sys.exit(1)`.

**VERDICT: Moderate** — will crash silently on any Playwright failure with no user-facing diagnostic.
