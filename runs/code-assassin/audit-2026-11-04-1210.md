### FINDINGS

**1. [CRASH RISK] Sub Main — no `Finally` to restore `SilentOperation`**
- **Location:** Sub Main, Phase 2 start (~line 440) through Phase 3 end (~line 695)
- **Description:** `ThisApplication.SilentOperation = True` is set before Phase 2
  begins, then restored via `ThisApplication.SilentOperation = bOrigSilent` only
  at the explicit "step 8" line near the end. If an exception escapes the per-file
  Try/Catch — e.g. during the `List(Of String)` construction, the `Sort` lambda, or
  the `HashSet` iteration over `oActualMap.Values` — the sub exits without restoring
  SilentOperation. Inventor then suppresses ALL dialogs for the rest of the session
  (until Inventor is restarted), breaking every subsequent dialog-driven iLogic rule.
- **Suggested fix:** Wrap the Phase 2–3 block in a Try/Finally:
  ```vb
  Try
      ' ... Phase 2 and Phase 3 code ...
  Finally
      ThisApplication.SilentOperation = bOrigSilent
  End Try
  ```
  The existing "step 8" restore line can then be removed.

**2. [ILOGIC] Phase 3 — `oDoc3.File` not null-checked before `.ReferencedFileDescriptors`**
- **Location:** Phase 3 inner loop, ~line 603: `For Each oFD3 As Object In oDoc3.File.ReferencedFileDescriptors`
- **Description:** In Inventor, `Document.File` can be Nothing for documents that
  are open in an unresolved or error state. A NullReferenceException here falls
  through to the outer `exP3` catch, which logs "P3-ERROR: [filename]" with no
  further detail — making the entry look like a save failure rather than an API
  access error. Under normal conditions the file should be fully open (Phase 2
  already SaveAs'd it), but in multi-user environments where the file is locked,
  partially-resolved, or on a mapped drive that dropped, this can hit.
- **Suggested fix:**
  ```vb
  If oDoc3.File Is Nothing Then
      Try : System.IO.File.AppendAllText(sLogPath, _
          "P3-FILE-NULL: " & sNewName3 & vbCrLf) : Catch : End Try
      Continue For
  End If
  ```
  Add this check immediately after confirming `oDoc3` is not Nothing.

**3. [ILOGIC] WalkTree — no Content Centre part exclusion guard**
- **Location:** `Sub WalkTree`, child-open block (~line 215–240) and rename-map
  computation (~line 245–260)
- **Description:** The recursion opens every `.iam` and `.ipt` whose path exists
  on disk and whose basename starts with `sOldPrefix`. Content Centre parts
  (`.ipt` files stored under `C:\...\Content Center Files\...`) can have filenames
  that begin with the same prefix pattern if the project prefix is short or generic
  (e.g. "PJ-" or similar). SaveAs'ing a CC part creates a detached copy with a
  fresh GUID but broken Content Centre metadata bindings — Inventor will not
  recognise it as the same standard component, and the assembly referencing it
  will show a substitution warning.
- **Suggested fix:** Before adding a child path to the rename map, check the
  document type or path:
  ```vb
  ' Skip Content Centre parts
  If oChild.DocumentSubType = kCCPartDocumentSubType Then Continue For
  ' Alternative: check path pattern
  ' If sRefPath.ToUpper().Contains("CONTENT CENTER") Then Continue For
  ```
  The `DocumentSubType` check is the most reliable; the path check is a fallback.

**4. [OPTIMISATION] `sLog` string accumulates full per-file detail but is only used for the final MessageBox**
- **Location:** Phase 2 loop body (~lines 420–595), Phase 3 loop (~lines 640–680)
- **Description:** `sLog` is concatenated with one line per file processed
  (`sLog = sLog & vbCrLf & "  SAVED: " & ...`). For a GA with 200+ parts this
  builds a string of several hundred KB in memory, all of which is thrown into a
  MessageBox that truncates at ~32 KB anyway. The log file already captures
  everything incrementally. The final `sSummary` string at step 9 (already
  counter-based) is what the MessageBox actually needs.
- **Suggested fix:** Remove the mid-loop `sLog = sLog & ...` assignments in
  Phases 2 and 3 entirely. The file log captures the full detail; use `sSummary`
  (already built from counters) for the MessageBox. This reduces peak memory
  usage for large assemblies and avoids the MessageBox truncation risk.
