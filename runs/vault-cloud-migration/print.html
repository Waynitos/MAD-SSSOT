SSA Final Verdict
Conditional Go — Six Conditions Must Be Met

The migration is technically viable and Autodesk-supported. The Vault stack on a cloud VM is the same software as on physical hardware. All file formats are preserved through the SQL + file store migration. However, 13 critical failure modes exist that standard IT testing will not catch — nine specific to Plant 3D and Inventor workflows. Until six named conditions are satisfied, go-live carries unacceptable operational risk.

Section 3
6 Go / No-Go Conditions
All six must be met before go-live. Binary — each is either satisfied or it is not.
1
Latency Measured & Within Threshold
Actual round-trip from every workstation through corporate proxy to cloud Vault. ≤40ms → Go. 40–70ms → AVFS cache required. >70ms → escalate to leadership. Largest 3 assemblies timed with 10 concurrent users.
2
Plant 3D Test Cases Signed Off by Operator
A Plant 3D daily user — not IT — must review and sign off the test case list. Must cover: check-in direction test, project.xml paths, lock file concurrency, isogen output, Data Manager connection, pipe spec catalog.
3
Version Matrix Confirmed Per Workstation
Vault client add-in version documented for every machine. Cross-referenced against Autodesk's official compatibility matrix for the cloud server version. Written confirmation from cloud provider or VAR.
4
Project.xml Path Remediation Documented & Tested
Confirm whether working folder path changes. If yes: audit all Plant 3D project.xml files, document every edit required, execute remediation in test environment, confirm every project opens successfully.
5
Rollback Procedure Executed in Test Environment
Run the rollback — not just document it. Confirm all files recoverable. Define maximum acceptable data loss window. Get engineering management sign-off in writing before migration proceeds.
6
All Checked-Out Files Cleared
Audit every checked-out file across all users. Define resolution procedure for each engineer. Hard technical prerequisite — migration does not begin until all files are checked in.
Highest single risk: Condition 2 — Plant 3D test cases not authored by a Plant 3D operator. This is the meta-risk that causes all other risks to go undetected. If only one condition can be prioritised, it is this one.

Section 5
8 Priority Test Scenarios
Run in this order. Run before go-live — not during. Document every deviation from on-premise behaviour.
00
Pre-test
Version Matrix — Before Anything Else
Confirm cloud Vault server version matches the Vault client add-in on your test machine. If they don't match — stop and escalate. A mismatch invalidates all subsequent test results.
01
Plant 3D
Wrong-Direction Test
Open a Plant 3D drawing from Vault Explorer (not from within Plant 3D). Edit it. Attempt to check in. Document exactly what happens — failure, success, or silent corruption.
02
Plant 3D
Concurrent Editing Race
Two users open the same P&ID simultaneously. Both edit and attempt to check in. Does the second user see the first user's lock file? What happens to the overwritten version?
03
Inventor
Large Assembly Timing
Open the three largest assemblies with 5–10 people simultaneously doing other Vault operations. Record time from click to fully loaded. Measure latency from each workstation separately.
04
Inventor
iLogic Rule Execution
Find drawings with iLogic rules reading Vault properties. Run each rule on the cloud system. Verify returned values match what Vault actually shows in the web client.
05
Plant 3D
Isometric Generation Path
Run isogen on a known P&ID. Confirm output appears in Vault under the correct revision. Compare content line-by-line against a known-good reference from the on-premise system.
06
All
Historical Revision Open
Find drawings with 5+ revisions. Open each old revision from Vault history. Confirm all open — not just the latest. This is the binary file integrity test for the migration.
07
AutoCAD
Sheet Set Batch Plot
Locate all .dst sheet set files. Run batch plot on each. Confirm all sheets plot and output is correct. Silent path failures only surface during batch plot operations.
